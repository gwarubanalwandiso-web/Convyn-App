# Testing

Run `pnpm test` for domain tests. The direct files contain six engine cases and three lifecycle cases. `pnpm test:integration` builds the API, prepares local `convyn_test`, starts an API process on 4019, and performs 127 HTTP assertions plus database checks. It verifies authorization, admin MFA, registration/login, provider review and eligibility, full request-to-review lifecycle, notification persistence, expiry/suspension, duplicate acceptance, competing-bid races and session rotation/revocation. It stops its own API process on completion.

After build and integration setup, `pnpm test:web` starts the API on 4000 and all five portals on 3000–3004, then exercises three journeys in real Chromium: the marketplace with messages, invoice PDF download and support; business procurement; and enterprise procurement. It verifies rendered form interaction and state updates without mocking the backend or database. The browser test uses the system executable by default; configure CHROMIUM_PATH or USE_PLAYWRIGHT_BROWSER=1 for another installation. Failure traces are ignored by Git and may contain synthetic test data.

Tests generate new fictional accounts per run; test data remains in the separate test database for inspection. No database reset is automatic. Do not run tests against production. Native/mobile runtime, payment sandbox, external delivery, full multi-policy enterprise behaviour and failure/load suites remain pending. The CI workflow is configured with PostgreSQL and browser installation but has not been executed on GitHub in this session.

The expanded integration suite covers conversation privacy/idempotency/read receipts, cancellation, disputes/admin responses, binary PDF validation, quoted earnings, tracking consent/expiry/revocation, scheduled drafts, cross-tenant HTTP and direct-DB rejection, procurement roles/budgets and versioned recommendation snapshots. Android/iOS exports are verified for both Expo apps; native component/device E2E tests remain outstanding.
